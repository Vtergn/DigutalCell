# 新主数据路线核验：心肌 TTM 与 Hyser

2026-09-28。对用户贴出的路线建议，核对原论文、官方数据页和已公开的 TTM 分析表。TTM 数值复算见 `ttm_public_data_audit.py`、`ttm_public_data_audit.json`、`ttm_feature_prediction_pilot.py`、`ttm_feature_prediction_pilot.json`。原始公共表保存为 `Data/ttm_public/ttm_original`，来源为论文作者的 [TTM GitLab 仓库](https://gitlab.com/bjvanmeer/ttm-algorithm/) 中的 `ttm` 文件。后续用户下载的 Dryad [Source Data.zip](https://datadryad.org/dataset/doi:10.5061/dryad.67c92vm) 已审计：压缩包仅含五份文字表；其中 `Source Data - Table 2 (raw).txt` 与 GitLab `ttm` 文件逐行完全相同（19,771 行，含表头；文件哈希因换行符不同）。因此以下统计和预测试验适用于用户下载的 Dryad 原始表。

## 结论先行

换主数据体系这个判断合理。**Hyser 是较稳的工程预测路线；TTM 是有真实前后配对的药物响应路线，但不能直接称为“单个心肌细胞的电—钙—收缩数字孪生”。** 2026 eLife 的电生理模型与 2019 TTM 的观测并非同一批细胞，也没有天然共享的 52 个真实参数标签。两套数据的结合需要跨平台观测模型和外部验证，不能把它们当作一套同步单细胞训练集。

## 1. 心肌：哪些事实成立？

[2026 eLife 工作](https://elifesciences.org/articles/110013)确实公开了电生理数字孪生的仿真代码，报告约 110 万模拟细胞和 52 个生物物理参数。完整模拟数据没有在线托管，仅提供 100 个示例细胞与生成代码；主模型是电生理，不包含与 TTM 同细胞配对的收缩测量。原论文自身对实验验证的边界有讨论，不能把模拟参数恢复视为真实细胞参数可辨识的证明。

[TTM 原论文](https://www.nature.com/articles/s41467-019-12354-8)确实同时记录光学 AP、Ca 与收缩，并在药物加入前后测量。药物实验的单位是**培养孔里的心肌细胞单层**：每孔约 40,000 个细胞；每个条件五孔、每孔拍三个区域。每点原始影像约 3.6 GB，但开放的分析表保存的是每次测量提取的 **10 个特征**，不是逐帧 AP/Ca/收缩曲线。固定起搏为 1.2 Hz，因此这批药物数据不能实证验证“基线建模后预测新起搏频率”。收缩量是光学运动表型，不是直接测得的收缩力或主动张力。

作者公开的 TTM 分析表中有 19,770 行、1,977 条“区域×阶段”测量、1,060 个区域 ID；`baseline` 1,039 条，加药后 938 条。**917 个区域**有前后配对，**747 个区域**的十项前后特征完整。ID 第三段是 1/2/3，按其余段汇总得到 **361 个候选培养孔**，其中 340 个有三个区域，和原论文协议高度一致；完整前后配对至少一处的候选培养孔为 **320 个**。这一 ID 解释虽有协议支持，仓库未明确写出 ID 字典，正式发表前应向原作者或原始表说明核实。

### 留孔预测试验

我把同孔的合格区域取平均，每个培养孔只占一行；对 **317 个**同药、同剂量且至少有另外两个孔可供学习的孔，逐孔留出预测十项 `log(加药后/基线)` 特征：

| 预测器 | 平均绝对 log 比值误差 | 解释 |
|---|---:|---|
| 加药后不变 | 0.267 | 只用该孔基线 |
| 同药同剂量其他孔平均变化 | 0.186 | 已知药物、剂量和群体效应 |
| 上项 + 本孔同项基线偏离校正 | 0.156 | 用训练孔估计固定岭惩罚的线性校正 |

从 0.186 到 0.156 的平均降幅为 0.030，按 12 种药物聚类重抽样的描述性 95% 区间约 0.026–0.036。然而十个校正系数全部为负；因为目标本身是 `log(post)-log(baseline)`，改善可能部分是测量误差/均值回归，**不能直接解释成个体生理参数已被识别**。

再用全部十项基线 AP/Ca/收缩特征，固定惩罚的线性模型预测三项收缩响应；它相对于仅使用同项收缩基线校正只从 0.203 降至 **0.200**，按药物聚类的差值区间 **-0.0006 至 0.0061**，包含零。这是很小、当前不稳的跨模态额外信号。它既不否定 AP→Ca→收缩机制，也不足以证明复杂多模态 posterior 模型会赢过简单条件基线。

所以 TTM 当前最实在的题目是：**培养孔级、已知药物和剂量条件下，基线多模态特征能否预测未见培养孔的药物反应，并给出校准的不确定性。** 测试必须按孔或整批次分开；三个拍摄区域不得分别进训练和测试。若测试未见过的药物，必须有独立提供的药理作用信息；仅给药名却没有同药训练例时不能期望从基线推断药物作用。

## 2. 骨骼肌：为什么更稳？

[Hyser 官方页面 v2.0.0](https://physionet.org/content/hd-semg/2.0.0/)确认 20 位被试、每人两天、256 路 HD-sEMG 同步五指力；EMG 2048 Hz，力 100 Hz。1-DoF、N-DoF、random task 都有真实力轨迹。数据的独立单位是**20 人**，连续窗口不能冒充独立被试，但它有明确的 Day 1→Day 2 评估结构。全库约 142 GB；初期无需下载手势识别 37.1 GB 和 N-DoF 58.6 GB，可从 1-DoF（29.3 GB）或 random（9.8 GB）中逐被试下载。

[NinaPro DB2](https://ninapro.hevs.ch/instructions/DB2.html) 与 [DB3](https://ninapro.hevs.ch/instructions/DB3.html)确有力模式任务和 12 路 EMG，但力数据集中在特定练习；它们与 Hyser 的电极布局、肌肉、协议和对象群体都不同。“Hyser 训练→NinaPro 直接外部泛化”是强域迁移试验，不宜作为首轮模型成功的必要条件。

用户贴文中的 OpenArm 需要明确版本：[OpenArm **Multisensor 1.0**](https://github.com/lhallock/openarm-multisensor)公开同步超声变形、sEMG 与肘部力；普通 [OpenArm 1.0](https://hart.berkeley.edu/datasets.html)主要是静态体积超声与动作捕捉，不能混称为同一份实时三模态数据。前者是骨骼肌机制验证候选，但对象是肘部/肱桡肌，不是 Hyser 的五指肌肉系统。

## 3. 取舍与下一步

如果用户坚持 **“细胞级力电数字孪生”**，TTM 的公开药物表不满足单细胞单位，也不提供可与 eLife 电压钳模型直接配对的完整波形；不能马上投入 50 万–100 万模拟细胞和 SBI 网络。可先把 TTM 作为**培养孔级药物响应与多模态可观测性基准**，要求简单跨模态模型稳定超越药物剂量均值、基线均值回归和批次基线，再考虑机制仿真耦合。

如果用户优先 **“公开数据 + 工程 AI + 可严格验证的电到力预测”**，Hyser 是更稳的主数据。推荐先做小规模 Day 1 校准→Day 2 预测试验，同时用留一被试评估个体适配；之后再决定是否值得建立空间编码器和动力学状态。它应准确称为**个体神经肌肉/肌肉系统模型**，而非单细胞数字孪生。

这两条都比继续在 Duke 上堆网络更有机会，但不会自动产生一区/二区级创新。TTM 的强问题是“多模态是否带来可验证的个体药物响应增益”；Hyser 的强问题是“跨日期的个体化能否稳定优于简单 EMG–force 校准”。目前的小试验支持 TTM 有药物响应预测信号，**尚未支持复杂的跨模态机制反演主张**。
