# 开发与实验约定

1. **保持来源可追溯。** 外部文件放 `Data/` 或 `external/`，记录论文/DOI、下载位置和许可；不要直接修改原始数据。新派生数据写到实验自己的输出目录。
2. **先写问题和留出规则。** 新实验在运行前写明模型、输入模态、细胞级划分、校准协议、封存目标、指标与停止条件。任何用来选模型的队列都不再称为最终确认队列。
3. **保留强基线。** 时变轨迹至少比较无响应、简单响应搬运与因果线性叠加；参数或负载预测至少比较合适的 ridge/直接预测和方程模型。只在相同观测预算下比较。
4. **区分验证层级。** 数值回归、同方程新细胞、留整个协议、跨方程、真实同细胞实验依次记录，不能用前一层替代后一层。报告中标明物种、单位、输入是指定长度还是外力。
5. **每个实验可重跑。** 脚本、参数范围、随机种子、依赖版本、输入清单、机器可读分数和简短报告放在明确位置。输出较大时保留 manifest 和原始生成脚本；不要把所有大文件加入 Git。
6. **修改主闭环先过回归。** 运行 `scripts/project_check.py`；改 90 状态接口时检查原单脉冲逐点回归和状态/局部长度数组。该脚本只保证工件完整性，不能替代生物学验证。
7. **清理须可解释。** 仅用 `scripts/clean_generated.ps1` 清理已列出的再生缓存。大型模拟输出和用户下载 ZIP 即使占空间，也应先核对依赖和恢复用途。

历史 `analysis/` 保持原路径，避免打断已发表方程移植和报告中的相对引用。新工作优先在独立子目录内组织 `README.md`、`src/`、`results/`；迁移历史模块时逐个处理并更新[项目地图](PROJECT_MAP.md)。
